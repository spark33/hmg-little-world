# Competition release APK

The required default staging filename is **`박상현_ROAMY_release.apk`**.

No APK is staged here until an authorized, signed, non-debuggable **vehicle release** passes static verification. Debug, preview and unsigned builds are not competition deliverables. Do not rename one to the required filename or supply a dummy APK to fill this directory.

Build in the cloud with the release owner's securely mounted signing configuration using [`scripts/build-release.sh`](../scripts/build-release.sh). See [release signing and validation gates](../docs/RELEASE.md). No production key is generated by these scripts.

Provide `ROAMY_RELEASE_CERT_SHA256` through trusted cloud environment configuration: the SHA-256 fingerprint of the release certificate approved by the owner. It is a public identifier, not a password; the staging tool captures certificate output privately and does not print certificate identities or the expected fingerprint. A valid signature from an unrelated certificate is rejected.

```sh
python3 scripts/stage-competition-apk.py
```

The default input is `android/app/build/outputs/apk/vehicle/release/app-vehicle-release.apk`. The script calls `verify-apk.py --release`, rejects debug/unsigned/preview packages and stale or mismatched web assets, matches the approved signer, and copies the exact privately verified APK bytes. It never overwrites an existing staged artifact; archive an earlier output explicitly before staging another build. `--build-tools`, `--web-dir` and `--output-dir` can select cloud workspace paths without changing the default filename.

Successful staging produces:

- `박상현_ROAMY_release.apk`
- `박상현_ROAMY_release.apk.sha256`
- `박상현_ROAMY_release.verification.json`

The sidecars contain public artifact hashes and static results. They explicitly **do not attest official Pleos runtime validation, driving-safety certification, organizer acceptance, market approval or a runnable vehicle entertainment state**. The production vehicle safety lock and all release gates still apply. Staging does not upload or submit anything externally.

Without an authorized release keystore and approved signer fingerprint, this directory should contain this README only. Complete official Pleos emulator testing and the competition's current submission requirements separately before handing off an APK.

Run the cloud staging policy tests with `python3 -B -m unittest discover -s scripts/tests -p 'test_stage_competition_apk.py' -v`. Synthetic unit fixtures stay in private temporary directories; they are never competition APKs. Actual debug-APK and stale-production-asset rejection were also checked separately without staging a release.
