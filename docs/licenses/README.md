# Third-party attribution material

The generated in-app text is `web/public/third-party-notices.txt`. It reproduces full third-party license/NOTICE material and does not place ROAMY's original code under a new license. Source metadata and this audit are not legal certification, competition acceptance, or approval to redistribute a proprietary SDK.

## Reproduce and verify

After `npm ci` in `web`, build the production bundle so Vite emits the exact package paths whose JavaScript survives bundling:

```sh
npm --prefix web run build
python scripts/generate-notices.py --bundle-inventory web/dist/bundle-dependencies.json
# Rebuild to copy the generated public text into web/dist and APK assets.
npm --prefix web run build
python scripts/generate-notices.py --check --bundle-inventory web/dist/bundle-dependencies.json
python -m unittest discover -s docs/licenses -p 'test_generate_notices.py' -v
```

The generator performs no network access. `--check` is read-only and compares exact generated bytes, source hashes, lockfile identity, installed package versions, and emitted-package scope. It fails if full license material is unavailable for a shipped package. Omitting `--bundle-inventory` conservatively treats all installed non-dev lock entries as shipped; this currently fails the two unresolved installed-only dependencies described below. Do not hand-edit the emitted bundle inventory to bypass a failure: rebuild it from the source with the Vite plugin.

The Android build must use a `web/dist` containing the latest generated text. Verify the bundled asset after building; do not substitute a historical APK. The notice reader remains behind the app's vehicle safety restrictions.

## Coverage and provenance

`runtime-dependencies.json` inventories every installed non-dev entry from `web/package-lock.json`, including nested duplicate package versions. It distinguishes the emitted JavaScript scope from the larger conservative installed graph. The current bundle identifies **13 shipped web packages among 68 installed non-dev entries**; this does not claim all 68 packages are redistributed.

For each package the inventory records exact path/version, declared license metadata, available notice paths and hashes, shipped status, and source-review notes. The generator recursively includes all files named LICENSE/LICENCE/COPYING/NOTICE with common suffixes, excluding nested `node_modules` because those have separate lock entries. Full font notices distributed inside Three.js are included conservatively; their presence does not mean ROAMY loads those fonts. Existing copyright and terms remain unchanged, including original line endings. Package metadata authors are labeled metadata, not invented copyright statements.

The npm tarball for `@react-three/fiber` 9.8.2 omits its license file. `upstream/react-three-fiber-9.8.2-LICENSE.txt` is the full official license fetched at the exact `v9.8.2` upstream tag. Its source URL/ref and SHA-256 are pinned in `upstream/sources.json`.

Additional audit-only supplements are retained for installed packages not identified in the emitted bundle:

- Draco 1.5.9: full official LICENSE at the version ref linked by its installed README, including all additional notices in that file.
- MediaPipe Tasks Vision 0.10.17: official upstream Apache 2.0 text pinned by commit, plus the actual 2022/2023 MediaPipe Authors license comments extracted from its installed `vision.d.ts`. No matching JavaScript-version Git tag was available; this limitation is recorded explicitly.
- Maath 0.10.8: release has MIT metadata and an embedded Max Kaufmann MIT notice for easing code, but no project-level LICENSE. Its later 2026 project license was not substituted for this older release. **Unresolved, unshipped**; shipping it requires completing upstream attribution review.
- Stats-gl 2.4.2: MIT metadata/README exist, but no full project-level license file was found. The npm gitHead points to source package version 2.3.1 and was not treated as exact version provenance. No copyright holder or year was invented. **Unresolved, unshipped**; shipping it requires completing upstream attribution review.

If tree shaking changes and either unresolved package becomes emitted, strict notice generation/checking fails. Resolve its actual license material or remove it from the shipped code; an SPDX identifier alone is not accepted as full license text.

## Android and remaining review gates

See [ANDROID.md](ANDROID.md) and the resolved [vehicle runtime dependency graph](ANDROID-RUNTIME-DEPENDENCIES.txt). Native OSS license texts and proprietary Pleos SDK terms are kept separate. Android dependency changes require a fresh resolved runtime graph and updated native attribution; the npm notice generator does not automatically resolve Gradle dependencies.

Before release, review the exact final web/APK artifacts, any newly emitted workers/WASM/assets, source modifications, attribution presentation, native transitive dependencies, and applicable SDK/competition/market terms. Build tooling and dev-only npm packages are outside the generated runtime scope. The project does not claim that this material completes every legal obligation or grants rights to proprietary Pleos components.
